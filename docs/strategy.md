# 云驿（YunYi）战略定位

> 2026-08-14 老板拍板。本文件是产品定位的事实源；实现细节以各期规格为准。

## 一句话定位

**本地订阅服务 + 配置导出（配置工厂）**——云驿管理你的订阅、节点与服务器链路，把「配置」作为交付物，输出给生态内任一客户端消费。

## 做什么（护城河）

1. **全协议订阅解析**：URI 列表与 Clash YAML 双格式，vmess / vless / trojan / ss / ssr / hysteria2 全协议归一化。
2. **多生态配置导出**：Clash/Mihomo YAML（已有）与 sing-box JSON（规划中）双出口——同样的节点库，喂给任何客户端。
3. **本地订阅服务**：把归一化后的节点以本地服务形式供客户端订阅。
4. **服务器与链路管理**：WG 中转链路建链/接管/监控、服务器测速（延迟/带宽/BBR/对测）。

## 不做什么（边界）

- **不做内核客户端**：不接管系统代理、不内置转发内核、不做托盘常驻转发——那是 Clash Verge 们的战场。
- **mihomo sidecar 仅限测速工具**：打包内置的唯一用途是节点真实代理连通性测速，不承载任何转发流量。
- **不运营订阅源**：不提供、不中转任何机场/订阅内容，只管理用户自有的订阅。

## 生态关系

与 Clash Verge 等客户端**共生而非竞争**：云驿产出配置，客户端消费配置。任何格式演进（新协议、新内核）对云驿是解析/导出面的一次扩展，而非产品转向。

## 品牌

- 产品名：**云驿（YunYi）**。
- 品牌名仅用于用户可见 UI 文案、App 显示名与发布通道；内部路径/目录/临时文件维持中性命名，品牌改名不牵连路径代码（铁律）。
