# 已添加服务器 IP 与关闭连接误报修复

## 已确认原因

原检测器只认识节点的完整 IP:代理端口，不认识同一服务器的 SSH 管理端口。云驿同时有代理流量和正常服务器直连时，管理连接会触发“同程序分流”判据。

实机 TCP 表还确认截图中多条 `[system process]` 是 PID 0 的 TIME_WAIT 残留。分类器此前没有排除这些已经关闭的连接。

## 用户确认的规则

- 应用内已添加的服务器、中转服务器与节点 IP 作为已知目标，覆盖所有端口和进程，不区分测速、SSH 或其他用途。
- 明确节点端口的现有“隧道出站”标签保留；其他未进入 mihomo 的已知 IP 连接标为“已知服务器”，不计入泄漏或疑点。
- 每轮采样重新从数据库生成 IP 集合。新增约下一轮（正常间隔 1 秒）生效；修改、删除同步生效。同 IP 尚有其他记录引用时继续保留。
- IPv4、IPv6 和 IPv4-mapped IPv6 均支持。域名仅使用已有系统 DNS 缓存的精确解析记录，不发起额外 DNS 查询，不把网段或相似域名加入。
- 这是按用户设定的目标白名单分类，不证明该连接的具体用途或安全性。云驿访问未添加公网 IP 时仍按原判据检测。
- CLOSED、TIME_WAIT、DELETE_TCB 不进入当前分类，也不参与源端口关联旁证；SYN_SENT 等尝试建立的连接仍保留。mihomo 自身已记录的连接继续展示。

## 验证

- 连接日志回归 45 项通过。
- 后续已知目标相关筛选 9 项通过（含独立实机测试）：覆盖所有端口/进程、同程序分流、动态增删改、同 IP 多引用、域名缓存和映射 IPv6。
- TCP 表解析 7 项、连接接管 5 项通过。
- 前端连接日志 24 项通过；产品与测试 TypeScript 检查、Vite 构建通过。
- 实机验证从只读数据库取出 7 个服务器 IP；当次快照过滤 81 条关闭连接。短暂建立到已保存服务器 `203.0.113.10:22222` 的连接，新的分类结果为 `KnownServer`，没有登录、执行远端命令或更改系统代理。
