# CDN 分享

在「分享 → 新建分享」选服务器，开启「通过 CDN 分享」，填写已开启 CDN 代理的域名，端口选自动或指定 HTTPS 端口。生成时保存该服务器设置，后续新建自动沿用。

源站需要已有 `/etc/letsencrypt/live/<域名>/` 有效证书和私钥。程序不会把普通域名误当成已配置 CDN，也不会通过更改整个区域的 SSL 模式绕过回源要求。CDN 须按同一 HTTPS 端口回源。

自动端口顺序：2083、2053、2087、2096、8443、443。指定端口被占用时直接报错；不会抢占现有 Xray、面板或分享监听。每份分享独占一个 CDN HTTPS 端口，全部耗尽时需要释放旧分享端口；当前未实现多个分享共用一个端口的虚拟主机路由。

支持 VMess/VLESS WebSocket 节点。Reality、原生 SS、Hysteria2、TUIC 不会被静默生成为“CDN 节点”。源站内部代理实例监听回环，外部路径为：

```text
客户端 → Cloudflare → 分享 HTTPS 服务（订阅下载 / WS）
                   → 分享计量/限速网关 → 分享独立代理实例
```

导出 `/cdn-ws/<网关端口>`，HTTPS 服务只接受本份清单列出的 WS 节点，并转发到对应网关。客户端不能指定任意目标，配额和到期阻断仍由网关执行。WebSocket 空闲 300 秒会断开，客户端可重新连接。

设置保存在 `settings.share_cdn_<server_id>`；分享的实际域名和端口保存在服务器 `share.json` 的 `cdn` 字段。旧清单没有此字段时沿用直连。设置变更只影响新建分享，不会悄悄改掉已发出的链接；已有 CDN 分享编辑节点时保留其域名、端口和凭据。

每份分享的证书副本归 vpnshare 用户所有、权限 600。`vpnshare-cdn` 续期钩子只在对应域名续期后更新其副本、重启仍在运行的订阅服务。创建失败会回滚分享目录、服务与端口规则，共用脚本/续期钩子保留供其它分享使用。

验证包含 Rust 创建/导出/端口分配测试、前端设置记忆测试，以及本机 TLS WebSocket → 实际 Python 网关 → 测试源站的双向流量、超额和到期测试。测试文件位于本地 tests 目录（该仓库忽略 tests）。
